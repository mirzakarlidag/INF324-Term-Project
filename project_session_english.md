# SULTAN N. TURHAN
## INF 324 Relational Databases
### Session Project

## OBJECTIVES:

The primary goal of this session project is to familiarize the student with database concepts. To achieve this, they must create a database based on a client's needs, going through all design stages up to database implementation. The student must use the methods seen in class to properly structure their database and solve conceptual problems.

## DESCRIPTION:

You (and your partner if one exists) decide to enter the field of database design consulting. You must find your subject for creating a database that you will maintain throughout your session project. This client (or subject) can be real or fictional.

In the first part of your session project, you must create the functional description of the database to be conceptualized. The functional description must be understood by all database users. First, you must define the tasks that will be executed by the database. You must identify the entities and write the data dictionary. Then, you must create the entity-relationship diagram that corresponds to the functional description of your database. Additionally, all constraints must be clearly identified.

In the second part, from the entity-relationship diagram you developed in the first part of your session project, you must transform this model into a relational model. To ensure that your database remains in a consistent state with minimal data redundancy, the relations must be normalized up to the 3rd normal form. Additionally, structural constraints must be clearly identified.

The third part of your project must be implemented on SQL Server 20XX or PostgreSQL DBMS. From your relational diagram, you must establish your database on the software. The database must include:
- **Five queries** that provide lists
- **Three stored procedures** that perform insertion, updating, and deletion of data
- **One view** that replaces a query using at least 5 tables
- **One index** on the most frequently used table in your project
- **One trigger**

The queries and stored procedures must be under user control through graphical interfaces.
